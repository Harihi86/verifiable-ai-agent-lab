## 1. Summary (10 bullets)

1. VERIFIED-IN-SOURCE. Herdr has 17 installable integration targets (`IntegrationTarget` enum, src/api/schema/integrations.rs:32-71). `claude`, `codex`, `cursor`, `grok` and `antigravity-cli` are targets; **Gemini is not**. Gemini exists only as a detection kind (`Agent::Gemini`, src/detect/mod.rs:47,102,129,158,204) with a 2-rule screen manifest (src/detect/manifests/gemini.toml:1-25) and no asset directory under src/integration/assets/.
2. VERIFIED-IN-SOURCE. Every in-scope hook integration is now **session-identity-only**: it registers exactly one agent event (Claude `SessionStart`, Codex `SessionStart`, Cursor `sessionStart`, Grok `SessionStart`, Antigravity `PreInvocation`) that invokes the hook with the single action `session`, and the hook only sends `pane.report_agent_session` (src/integration/targets.rs:124-159, 160-224, 1246-1301, 1585-1631, 1714-1762; src/integration/mod.rs:282). Lifecycle state (idle/working/blocked) for all five comes from screen manifests, not hooks (src/agent_resume.rs:163-176 + src/app/actions.rs:1500-1505 force `herdr:claude|codex|cursor|grok` state reports to be treated as session-only).
3. VERIFIED-IN-SOURCE. Callback mechanism differs by OS. Unix `.sh` assets embed Python and write one JSON-RPC line (`{"id","method":"pane.report_agent_session","params"}`) directly to the AF_UNIX socket named by `HERDR_SOCKET_PATH` (claude sh:25-100, codex sh:25-98, cursor sh:12-59, grok sh:25-103, antigravity sh:26-75). Windows `.ps1` assets instead exec `$env:HERDR_BIN_PATH pane report-agent-session <pane> --source herdr:<agent> --agent <agent> --seq N --agent-session-id ID [...]` (claude ps1:32-53, grok ps1:46-58). Both gate on `HERDR_ENV=1` and `HERDR_PANE_ID`; the sh variants also require `HERDR_SOCKET_PATH` and `python3` on PATH (claude sh:20-23).
4. VERIFIED-IN-SOURCE. Hook install writes are idempotent and surgical for Claude/Codex/Cursor (exact-command matching, other users' hooks preserved: src/integration/claude_settings.rs:284-340; src/integration/tests.rs:1036-1110), block-owned for Antigravity (top-level `"herdr"` key rewritten wholesale: targets.rs:1618-1623), and file-owned for Grok (`~/.grok/hooks/herdr.json` + script, nothing else touched: targets.rs:1742-1756).
5. VERIFIED-IN-SOURCE. Drift detection is weak for Claude/Codex/Cursor: `herdr integration status` only parses the `HERDR_INTEGRATION_VERSION=` marker in the hook script (src/integration/registry.rs:444-462, 518-531). Only Grok (`herdr.json` compared to canonical JSON, registry.rs:403-414, 471-480) and OpenCode re-validate the agent's config. A third party that removes Herdr's `SessionStart` entry from `~/.claude/settings.json` leaves status reporting "current" (INFERRED consequence).
6. VERIFIED-IN-SOURCE. `herdr agent start --kind K` has **no per-kind command table, args, env, or launcher**. It types `interactive_agent_executable(K)` plus the user's `-- args` into an existing shell pane as a shell command (src/app/agents.rs:197-225; executable table src/detect/mod.rs:153-186). The only kind-specific behaviours are: Cursor executable is `cursor-agent.cmd` on Windows (detect/mod.rs:159-165); Codex `resume <id>` launch args are persisted (src/agent_resume.rs:135-151); Codex on Windows gets a paste-boundary key before Enter (src/app/api/agents.rs:15-33, 252-259); Copilot gets a focus-gained event (api/agents.rs:238-249); Codex is accepted as ready in `unknown` state (src/cli/agent.rs:613-618).
7. VERIFIED-IN-SOURCE. Grok can be started and prompted purely through Herdr: `herdr agent start <name> --kind grok --pane <id>` then `herdr agent prompt <name> "..." --wait`; readiness/blocked detection comes from src/detect/manifests/grok.toml (OSC title, OSC 9;4 progress, `[stop]` chip, `┃` option lists). Installing the Grok hook is only needed for session-id capture/restore (`grok --resume <id>`, agent_resume.rs:288-290). Grok's hook prefers the `GROK_SESSION_ID` env Grok injects (grok sh:69, ps1:38).
8. VERIFIED-IN-SOURCE. Every pane spawned by Herdr receives `HERDR_ENV=1`, `HERDR_SOCKET_PATH`, `HERDR_BIN_PATH`, and (managed identity) `HERDR_WORKSPACE_ID`, `HERDR_TAB_ID`, `HERDR_PANE_ID`; it strips inherited `CODEX_THREAD_ID`, `OMPCODE`, `CLAUDECODE`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_MESSAGING_TOKEN` (src/pane.rs:184-217; src/integration/env.rs:28-33). Windows additionally sets `HERDR_PANE_RUNTIME_ID` for Git-Bash panes (src/platform/windows.rs:524, 1082-1095).
9. VERIFIED-IN-SOURCE. Windows transport is a named pipe `\\.\pipe\<socket-path>` with an SDDL DACL restricted to SYSTEM + the user's account SID plus a mandatory integrity label (`HI` when the server is elevated unless `allow_unelevated_clients`) (src/platform/windows.rs:30-80, 126-131; src/ipc.rs:66-80). Unix uses a 0600 unix socket (src/server/socket_paths.rs:11-12, 72-75).
10. VERIFIED-IN-SOURCE. The CLI/hook test suites (tests/cli/hooks.rs, tests/cli/agents.rs, etc.) are compiled only on non-macOS Unix (tests/cli.rs:1), so hook-asset behaviour is not exercised by integration tests on Windows; Windows coverage is unit-level in src/integration/tests.rs (e.g. 1182-1234, 1238+) and tests/windows_server_security.rs.

## 3. Agent dispatch pipeline (step-by-step)

All VERIFIED-IN-SOURCE unless noted.

1. **CLI parse** (src/cli/agent.rs:289-357): `herdr agent start <name> --kind KIND --pane ID [--timeout MS] [-- <agent-args...>]`. `--kind` must satisfy `detect::parse_agent_label` (src/detect/mod.rs:188-228: canonical labels plus aliases such as `claude-code`, `cursor-agent`, `antigravity-cli`, `grok-build`). The advertised kind list is `Agent::ALL` (24 kinds; src/cli/spec.rs:457-462; detect/mod.rs:71-96).
2. **Pin and send** (cli/agent.rs:358-404): the CLI records the pane's terminal id, sends `Method::AgentStart{name, kind, pane_id, args, timeout_ms}` over the API socket, and retries on `agent_pane_busy` only while the pane shell is still initializing.
3. **Server validation** (src/app/agents.rs:145-196): name grammar `[a-z][a-z0-9_-]{0,31}` (15-20); args rejected if they contain control chars (156-162); duplicate name check; pane must resolve to a live terminal that is not already an agent (187-189); the pane's foreground must be an available shell (`platform::available_pane_shell(child_pid)`, 194-195, 423-429).
4. **Command synthesis** (app/agents.rs:197-200): `argv = [interactive_agent_executable(kind)] ++ args` (table at detect/mod.rs:153-186: `claude`, `codex`, `gemini`, `cursor-agent[.cmd]`, `agy`, `grok`, ...). `platform::interactive_shell_command(&argv, &shell_name)` turns it into one line for the pane's shell:
   - Linux/macOS: POSIX single-quote quoting, or PowerShell quoting if the pane shell is pwsh (src/platform/mod.rs:515-545; linux.rs:324-342; macos.rs:217-235).
   - Windows (src/platform/windows.rs:1103-1149): builds a PowerShell script `if((Get-Command <exe> -ErrorAction SilentlyContinue).CommandType -eq 'ExternalScript'){& <exe> <args>}else{Start-Process -FilePath <exe> -ArgumentList '<cmdline>' -NoNewWindow -Wait}`; typed as-is into powershell/pwsh panes, otherwise wrapped as `powershell.exe -NoLogo -NoProfile -EncodedCommand <base64>` for cmd.exe panes.
5. **Submission** (app/agents.rs:201-225): `encode_api_submission` (bracketed-paste aware) -> `validate_input_submission` -> `terminal.begin_managed_agent(name, kind, now, settle=3s, timeout)` (default 30 s, must be >3000 ms and <=300000 ms, lines 8-12, 202-209) -> bytes written to the PTY. If args are exactly `resume <id>` and kind is Codex, the session is persisted up front (src/agent_resume.rs:135-151).
6. **Readiness wait** (cli/agent.rs:562-638): polls `agent get`; fails with `agent_name_lost` if terminal id or name changes, `agent_kind_mismatch` if the detected agent label differs, `agent_not_ready` if `blocked`, `agent_start_failed` if idle without launch pending; succeeds on `idle|done` with `interactive_ready`, or for Codex on `unknown` with `interactive_ready` (613-618).
7. **Identity/state sources feeding readiness**: foreground-job process identification `identify_agent_in_job` (detect/mod.rs:249-289; Windows snapshot walk windows.rs:1551-1600, 1825-1850), `HERDR_AGENT=<label>` env hint read from the process environment on Linux/macOS only (platform/mod.rs:602-611; linux.rs:786-796; macos.rs:1005-1012), and screen manifest detection `detect_agent_with_osc` (detect/mod.rs:305-328) using regions `osc_title` / `osc_progress` captured from OSC 0/2 and OSC 9;4 (src/pane/osc.rs:1066-1200 tests show `9;4` handling).
8. **prompt** (src/app/api/agents.rs:82-137, 139-269): `validate_agent_prompt` rejects empty text, `blocked` agents (`agent_blocked`), pending launch (`agent_not_ready`), and panes whose foreground is no longer the expected agent (`runtime_hosts_agent`, app/agents.rs:431-451). `submit_agent_prompt` sends focus-gained for Copilot, appends a Right-arrow paste boundary for Codex on Windows, then queues text + Enter with a 300 ms delay (`AGENT_PROMPT_SUBMIT_DELAY`, line 13). `--wait` is one request (`AgentPromptWaitOptions`, src/api/schema/agents.rs:35-43).
9. **send-keys / read / explain / wait**: api/agents.rs:383-435, 271-310, 312-381 (explain runs `detect::manifest::explain_with_input` against the live screen); `agent wait` is `Method::AgentWait{target, until[], timeout_ms}` (cli/agent.rs:506-560; schema agents.rs:25-32).
10. **No per-kind env injection at dispatch**: nothing in `start_agent` adds env; the pane env comes solely from pane spawn (src/pane.rs:184-217). INFERRED: because the agent is typed into the user's shell, shell rc files and PATH decide which `grok`/`claude` binary runs.

- Integration: version 3 (mod.rs:322). Config dir resolution: `GROK_CONFIG_DIR` (Herdr-only override/test seam) > `GROK_HOME` (grok's own) > `~/.grok` (env.rs:197-207). Install requires the dir to exist (targets.rs:1735-1740), writes `hooks/herdr-agent-state.{sh,ps1}` and `hooks/herdr.json`; uninstall deletes both (1764-1779). Command string: unix `sh '<path>' session` (note `sh`, not `bash`, targets.rs:1707-1711); Windows `powershell -NoProfile -ExecutionPolicy Bypass -File "<path>" session` (targets.rs:1700-1704 -> command.rs:10-23). Status is "outdated" if `herdr.json` is missing or differs semantically (registry.rs:403-414, 471-480; tests.rs:5040).
- Hook behaviour (grok sh:59-89; ps1:23-58): accepts event name absent or any of three spellings; session id from `GROK_SESSION_ID` env then `session_id`/`sessionId`; forwards `source` as `session_start_source` (server normalises to `startup|resume|clear|compact|branch|new|fork|select`, agent_resume.rs:153-161). Reports `agent: "grok"`, `source: "herdr:grok"`.
- Resume: `grok --resume <id>` (agent_resume.rs:288-290); `herdr:grok` is an official source (328-350) and a reserved native-state source (163-176), so a `pane.report_agent` from `herdr:grok` never sets lifecycle state.
- Starting/prompting Grok purely through Herdr (no Codex involvement): requirements are (a) a Herdr pane sitting at an interactive shell prompt, (b) `grok` resolvable by that shell (on Windows via `Get-Command grok`, i.e. `grok.exe|.cmd|.ps1` on PATH; `command_path_candidates` registry.rs:139-159 is used only for availability display), (c) nothing else. Then `herdr agent start g1 --kind grok --pane <id> [-- <grok args>]`, `herdr agent prompt g1 "<text>" --wait`, `herdr agent read g1`, `herdr agent send-keys g1 ...`. The hook install is optional and only affects session capture. INFERRED: because the `grok.toml` idle rule relies on OSC title/progress or the `ctrl+.:shortcuts` footer, a Grok build that changes its footer text would make `agent start` time out rather than fail fast.
- Claude-compat side effect: Grok imports Claude-style hooks and emits `new`/`load` sources, which is why the Claude `SessionStart` matcher is restricted (claude_settings.rs:17-19; docs integrations.mdx:114, DOC-ONLY).

## 5. Claude Code hooks: what Herdr writes, merge semantics, conflict analysis

What is written (VERIFIED-IN-SOURCE):
- `~/.claude/hooks/herdr-agent-state.sh` (unix) or `.ps1` (Windows), marker `HERDR_INTEGRATION_VERSION=11` (mod.rs:42-52; targets.rs:131-134). The directory `~/.claude` must already exist (targets.rs:127-132).
- `~/.claude/settings.json` -> `hooks.SessionStart` gets exactly one Herdr entry: `{"matcher":"^(startup|resume|clear|compact|fork)$","hooks":[{"type":"command","command":"bash '<abs path>' session","timeout":10}]}` on unix, command `powershell -NoProfile -ExecutionPolicy Bypass -File "<abs path>" session` on Windows (claude_settings.rs:19, 76-82, 350-359; command.rs:10-34).
- Hook events registered: **SessionStart only**. Not registered: Stop, Notification, PreToolUse, PostToolUse, UserPromptSubmit, SubagentStop, PermissionRequest, SessionEnd. Those appear only in `HOOK_REMOVALS` so that older Herdr installs (v<=9 lifecycle hooks) are cleaned up (claude_settings.rs:26-63; mod.rs removed-event lists for other agents 118-178, 233-246).

Merge semantics (VERIFIED-IN-SOURCE, claude_settings.rs):
- The file is parsed twice: strictly as JSON into serde (`parse_value`, 541-548) to compute the desired tree, and as a CST with `jsonc_parser` using strict options (no comments, trailing commas, single quotes: 577-587) to apply minimal textual edits that preserve the user's formatting. Duplicate keys anywhere abort the edit (550-575). After editing, the result is re-parsed and must equal the desired tree or install fails with "failed to safely update claude settings" (526-535).
- Idempotency: an entry whose `hooks[]` already contains a `type:"command"` with the identical command string is left alone (config_edit.rs:60-105). An existing Herdr SessionStart entry that differs from canonical (e.g. matcher edited) is removed by command match and re-added canonically (284-340, 253-279).
- Removal matches only exact Herdr command variants: current command, legacy `bash '<path>' <action>`, and on Windows the legacy `.sh` path (config_edit.rs:368-381; file_ops.rs:13-33). Entries are deleted only when their `hooks[]` becomes empty; an event key is deleted only when its array becomes empty (claude_settings.rs:325-337). Foreign commands in the same group survive (test tests.rs:1036-1110 keeps `echo keep-post` etc.).
- Compact (single-line) objects/arrays are appended compactly to avoid reflowing the user's file (227-232, 259-270, 373-420).
- Writes go through `config_file::write_config`: rejects hard-linked targets, follows symlinks (including dangling), writes a private temp file and replaces atomically on unix; on Windows uses the backup-first in-place path (config_file.rs:15-80, 88-135; docs integrations.mdx:56 DOC-ONLY for the Windows backup semantics).
- Uninstall removes Herdr's entries by the same command matching and deletes the script; it never touches `settings.json` otherwise (targets.rs:575-601; claude_settings.rs:97-126).

Hook runtime guards (VERIFIED-IN-SOURCE, claude sh:15-58; ps1:9-29): exits 0 silently unless action is `session`, `HERDR_ENV=1`, `HERDR_PANE_ID` set (sh also needs `HERDR_SOCKET_PATH` and `python3`); ignores payloads with `CURSOR_VERSION` env or `cursor_version` field (Cursor's Claude-compat hooks), any `hook_event_name != SessionStart`, and subagent payloads (`agent_id`). It reports `session_id`, optional `transcript_path`, and `source`; it never sends a state. Socket send has a 0.5 s timeout and swallows all errors (sh:88-99).

Server side (VERIFIED-IN-SOURCE): `pane.report_agent_session` -> `handle_pane_report_agent_session` (src/app/api/panes.rs:1599-1643) -> `AppEvent::AgentSessionReported` -> `set_agent_session_ref_for_session_start` (src/app/actions.rs:1543-1561). Per-source monotonic `seq` guard (`hook_report_is_newer`, src/terminal/state.rs:1946-1952). These methods are classified as UI-changing requests (src/api/mod.rs:22-69) and as "routine" for logging (src/logging.rs:105-117). There is no per-method authentication beyond socket/pipe ACLs (INFERRED from reading src/api/server.rs handle_connection region; no role checks found).

Conflict analysis with a third-party plugin (e.g. ECC) writing hooks into the same `settings.json`:
- Additive third-party entries (own commands under SessionStart/Stop/PreToolUse/...) are preserved by Herdr install/uninstall and vice versa, provided the third party also edits rather than replaces (VERIFIED by removal semantics above).
- If the third party serialises the whole file and drops Herdr's entry, Herdr's hook silently stops firing and `herdr integration status` still says `current (v11)` because status reads only the script marker (registry.rs:444-462). Repair = `herdr integration install claude` (idempotent). INFERRED gap; no settings re-validation exists for Claude.
- If the third party writes JSONC (comments/trailing commas) or duplicate keys, Herdr's next install/uninstall fails hard without modifying the file (strict parse 577-587, 550-575). INFERRED: this is the most likely practical conflict with hand-edited or tool-generated settings files.
- If the third party reports agent state itself, it must use a non-`herdr:` source via `pane.report_agent`; `herdr:claude` reports are coerced to session-only (actions.rs:1500-1505) and docs forbid the prefix (add-herdr-support.mdx:48, DOC-ONLY). Conflicting labels are resolved by `effective_known_agent` and process detection (state.rs:2052-2055, 2078-2099).
- Both Herdr's hook and a third-party SessionStart hook run; ordering is Claude's concern. Herdr's entry carries `timeout:10`.

## 7. Windows/macOS platform differences

VERIFIED-IN-SOURCE unless noted.
- **Transport**: Unix = unix domain sockets, 0600 (socket_paths.rs:11-12, 72-75; ipc.rs:54-64). Windows = named pipe `\\.\pipe\<path string>` created with security descriptor `D:P(A;;GA;;;SY)(A;;GRGW;;;<user SID>)S:(ML;;NRNW;;;HI|ME)`; integrity label is `HI` when the server token is elevated unless `allow_unelevated_clients` (windows.rs:26-80, 126-131; ipc.rs:66-80); a marker file is written at the socket path (ipc.rs:78). The private client-protocol pipe uses `D:P(A;;GA;;;SY)(A;;GA;;;OW)` (ipc.rs:144-163). Tested by tests/windows_server_security.rs:49+ (low/medium/high integrity tokens). Windows hooks therefore cannot use AF_UNIX from PowerShell and call the CLI via `HERDR_BIN_PATH` instead (all 13 ps1 assets contain `report-agent-session`; copilot/letta/qwen ps1 also reference `HERDR_SOCKET_PATH`).
- **Hook script selection and commands**: `.ps1` vs `.sh` chosen at compile time via `cfg!(windows)` (mod.rs:42-51, 53-62, 247-256, 258-267, 311-321). Registered command on Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File "<path>" <action>` (command.rs:12-23); Antigravity uses `-EncodedCommand <base64 UTF-16LE of "& '<path>' session">` (command.rs:36-46; targets.rs:1633-1642). Unix: `bash '<path>' <action>` except Grok `sh '<path>' session` (targets.rs:1707-1711). Windows ps1 hooks read stdin as raw UTF-8 bytes to survive non-UTF-8 code pages (claude ps1:13-16; enforced by tests.rs:1182-1234; CHANGELOG line 15 DOC-ONLY). On Windows install also deletes a stale legacy `.sh` next to the `.ps1` if it carries a Herdr marker (file_ops.rs:13-33).
- **Agent launch**: PowerShell `Get-Command`/`Start-Process` wrapper and cmd.exe `-EncodedCommand` fallback (windows.rs:1103-1149); `cursor-agent.cmd` executable (detect/mod.rs:159-165; agent_resume.rs:269-280); availability probing tries `.exe/.cmd/.bat/.ps1` (registry.rs:139-159); Codex standalone binary under `%CODEX_HOME%\packages\standalone\releases\*\bin\codex.exe` counts as available (registry.rs:181-202); Qodercli/Hermes Windows aliases (registry.rs:108-116, 204-223).
- **Prompt delivery**: Codex on Windows gets a Right-arrow paste boundary before Enter because ConPTY lacks bracketed paste (api/agents.rs:15-33, 252-259; test 503-535). `submission_deadline` is only honoured on Windows (231-237).
- **Process attribution**: Windows uses a process snapshot with a 250 ms cache, ancestry walk, Git-Bash detection, and the `HERDR_PANE_RUNTIME_ID` env marker (windows.rs:519-524, 1082-1095, 1551-1600, 1648-1800, 1825-1850, 2184-2375). No `HERDR_AGENT` env hint on Windows (platform/mod.rs:597-600). macOS reads argv/env via `KERN_PROCARGS2` (macos.rs:556-640, 999-1082).
- **Config file writes**: unix atomic temp+rename (config_file.rs:72-135); Windows backup-first in-place replacement with ACL preservation (windows.rs:262-441; docs integrations.mdx:56 DOC-ONLY).
- **macOS specifics**: server adopts the user launchd bootstrap context via `HERDR_MACOS_SERVER_CONTEXT` (macos/bootstrap.rs:7-50); POSIX quoting (macos.rs:217-235); terminal canonical line-input limit check for `pane run`/`agent start` (skills/herdr/SKILL.md:189, DOC-ONLY; not located in code during this pass).
- **Integration support on Windows**: all 17 targets are allowed (registry.rs:65-95); Devin dir is `%APPDATA%\devin`, Hermes `%LOCALAPPDATA%\hermes` (env.rs:74-85, 142-162).
